# linecop

The gate fails any file over its limit. Learn the limit before you write, so
the change is spent on the work, not on squeezing a file back under.

## Before growing a file

```sh
linecop --baseline 85   # every file at 85%+ of its limit; default 100 = only violations
```

If the file you are about to grow is listed, decide the split first and put
the new code in its new home from the start. Do not make room by deleting
comments, joining lines or compressing prose.

Trust linecop's numbers, not `wc -l`: `count_mode` decides what counts. A
violation already there is not yours to fix in passing; name it and move on.

## Where a limit comes from

`.linecop.yaml`, found by walking up from the scanned path to the working
directory. Read it before writing, not after the gate trips.

- `limits`: per language, by tokei name (`Rust`, `Markdown`, `Python`). A
  language with no entry is not checked.
- `overrides`: per glob; the first match wins. Each sets `limit`, `max_bytes`,
  or `exclude: true`.
- `count_mode`: `total` (default), `code`, or `code-comments`.
- `exclude_dirs`, `include_hidden`: what the scan skips.

A glob matches the path as scanned: scanning `.` yields `./src/x.rs`, which
`src/x.rs` does not match. Write `./src/x.rs` or `**/x.rs`, and check the
override took effect with a run.

## Split, or raise the limit

Split by default, along a real seam: a module, a section, a test file.

Raise only when splitting would hurt: generated code, a data table, a file a
tool requires whole. Use a narrow override, never the language-wide limit, and
record why in a comment so the number is not re-litigated:

```yaml
overrides:
  # Generated by scripts/gen_tables.py; edit the script, not this file.
  - pattern: "**/src/tables.rs"
    exclude: true
```

Generated files get `exclude`; hand-written ones that are honestly big get a
`limit`.

## Scripts and gates

- `-q`: exit code only. `0` clean, `1` violations, `2` the check never ran
  (bad config, unknown language, bad glob): a broken gate, not a big file.
- `--format paths`: one path per line. `linecop --format paths | ejectest
  apply --files-from - src/` moves oversized inline Rust tests out.
- `--format json`: `lines`, `limit`, `baseline-limit` per file, plus `bytes`,
  `max_bytes`, `baseline-max-bytes` when a byte cap applies.

Never parse the text output.
